# Pilot 设计方案

状态：执行层提取及依赖/Host 基线已完成，已进入 Pilot 首轮界面适配；品牌、首页、双列导航和本地项目分组见 PILOT-UI.md。项目执行目录恢复、跨端归属、完整设置与产品身份仍未完成。进度见 IMPLEMENTATION.md，底层验证见 EXECUTION-LAYER.md。

## 1. 产品定位

编程与电脑操作并重的通用 Agent。复制 nanoMuse 的核心执行层，沿用其行为，在此基础上重新设计桌面布局并新增项目会话。PI-Desktop 仅为体验参考，不是代码基线。Pi 作为后续扩展。

核心原则：除项目会话和布局外，会话、任务、工具、权限、停止、同步、后台运行、配置及数据管理均以 nanoMuse 实际实现为准。此前讨论的自研队列、会话分支、三级配置、统一新数据库、项目锁及设备独立 nexo 均不作为新增需求。

## 2. 桌面布局

左侧由两列组成：

1. 第一列是窄垂直图标栏。点击图标后显示对应第二列菜单或页面。
2. 第二列显示当前菜单。聊天菜单由 nexo、会话、项目三组组成。
3. 主区域展示会话或当前页面。执行结果、电脑操作画面等沿用上游展示方式，不强制新增通用右侧 IDE 工作区。

```text
┌──────┬────────────────────┬──────────────────────────────┐
│ 聊天 │ nexo               │ 会话标题                     │
│ 搜索 │   主要聊天         ├──────────────────────────────┤
│      │                    │                              │
│      │ 会话             ＋│ 消息、工具与审批             │
│      │   整理文件         │                              │
│      │   研究一个问题     │                              │
│      │                    │                              │
│      │ 项目             ＋│                              │
│      │ ▾ Pilot            │                              │
│      │   界面开发         ├──────────────────────────────┤
│      │   修复问题         │ 输入框与现有操作             │
│ ☰    │ ▸ 个人网站         │                              │
└──────┴────────────────────┴──────────────────────────────┘
```

第一列首版以聊天、搜索为入口；设备入口在中继阶段接入。第一列不放置独立设置图标。

视觉参考：浅色中性背景、小号分组标题、紧凑列表、选中行浅灰圆角高亮、长标题省略。初始尺寸建议图标栏约 52 px、第二列约 260 px，属于原型调优值，不是执行层约束。深浅色主题与国际化沿用上游能力。

## 3. 聊天菜单

| 分组 | 定义 | 规则 |
| --- | --- | --- |
| nexo | nanoMuse 主要聊天 | 固定入口，保持上游主会话选择、连续性和同步规则 |
| 会话 | nanoMuse 旁聊 | 复用现有创建、排序、置顶、重命名、归档等已具备操作 |
| 项目 | 按文件夹组织的开发会话 | 一个项目下可有多个开发会话，使用该项目工作目录 |

“会话”标题右侧加号新建旁聊。“项目”标题右侧加号选择文件夹，空状态不另显示“＋打开项目”；搜索统一使用第一列搜索入口，不在会话列重复放置搜索框。项目可折叠，项目入口提供新建开发会话。项目会话不重复列入旁聊，不可被主会话自动识别逻辑误选为 nexo。

项目与会话菜单只提供已实现且语义明确的操作。从列表移除项目不删除磁盘目录；会话删除等行为沿用上游，不额外设计文件回滚。

## 4. 项目会话，唯一新增业务能力

优先以 DSH 工作区表示项目，复用原会话：

```text
选择文件夹 → 创建或打开工作区 → 项目出现在列表
                                  ↓
                         在工作区创建开发会话
                                  ↓
                    恢复会话时保持原工作目录
```

- 三类会话首版均使用 DSH，不另建编程引擎。
- 项目开发可调用文件、搜索、终端、MCP、Skills 及电脑操作。
- nexo、旁聊仍可使用上游支持的编程和电脑操作能力，不设人为能力壁垒。
- 项目会话仅增加必要的工作区关联、导航分组与跨端归属信息。
- 不新增自动 Git worktree、容器、完整 IDE 或自研项目任务锁。
- 项目目录属于执行设备。远程客户端不能按自己的本地路径解释或重写该目录。
- 会话持久化、历史、压缩及并发处理沿用上游，差异只在项目适配必需处增加。

## 5. 对话与设置

标题、消息区、输入区和工具卡片仅做布局与视觉调整。沿用原发送、停止、工具展示、审批、错误、截图与操作轨迹。不得把“保留功能”写成“已全部验证可用”。

会话内容区支持多个会话标签：打开会话时复用已存在标签，支持拖拽排序、关闭和右键关闭当前/其他/右侧/全部。关闭标签仅关闭界面入口，不归档、删除或取消会话；全部关闭后显示空工作区，可从左侧重新打开。标签顺序属于本地导航偏好，会话与任务继续由 DSH 管理。

设置界面可重新组织分类与视觉，但配置数据格式、凭据保存、校验和生效时机沿用 nanoMuse/DSH。首版不建立全局、项目、会话三层新覆盖体系。

## 6. 左下角菜单

第一列底部 `☰` 打开参考图中的弹出菜单，向右上方展开：

```text
键盘快捷键                  [实际快捷键]
设置                        [实际快捷键]
──────────────────────────────────────
自动化任务
插件
收起聊天列表
```

- 浅灰背景、圆角、阴影；图标左对齐，快捷键右对齐，悬停高亮。
- 点击外部或 Esc 关闭，支持键盘导航与可见焦点。
- 设置、快捷键等接入上游已有入口，不为视觉重写行为；不提供“关于 Pilot”页面或菜单入口，界面不展示“基于 DeepSeek Harness”页脚。源码许可证和来源声明继续保留。
- 快捷键按实际绑定显示，不照抄截图中的未核对键位。
- 自动化任务、插件只连接已纳入当前版本的真实入口，不展示不可用空页面。
- 不提供“报告问题”页面或菜单入口；保留内部日志和故障诊断能力。
- 收起聊天列表仅折叠第二列，保留第一列和恢复入口。

## 7. 中继与手机端

后续复用 nanoMuse 的中继、认证、设备 Hub、同步、远程审批及停止机制，不设计替代协议。nexo、旁聊、项目开发会话都必须纳入远程访问验收。

不强制改成“每个设备独立 nexo”，不把新的设备选择器作为首版布局前提。上游的账号主会话、同步与执行设备关系经源码验证后保持兼容。

项目会话需补工作区关联和执行目录的必要支持。沿用上游权限边界，远程请求不能改变项目目录归属或绕过审批。

Android 和 iOS 都在产品范围。保留各自已有本地 Agent 能力及远程电脑访问。iOS 的跨应用操作能力不能承诺与 Android 对等；iOS 构建、签名与真机验收需要 macOS/Xcode，当前 Windows 环境只能完成有限静态研究。

## 8. 精简与扩展

首版不展示动态形象、媒体生成、Feed/Ideas/Goals/Library 等外围页面，以及官方免费模型、额度计费和企业聊天接入。若执行层仍依赖其中的服务，保留必要内部实现，不直接删除整块模块。弹出菜单中的自动化入口按现有可用能力决定，与隐藏 Goals 页面不是同一个决定。

MCP、Skills 和插件相关行为沿用上游。Pi 编程插件单列为后续扩展，相关开源桥接只作为候选，不承诺兼容或引入。

## 9. 实现边界

先完成 Windows 桌面基础版，再实施中继，随后 Android 和 iOS。上游原有其他桌面平台适配尽量保留，但不能在未构建测试前宣称支持。

不主动提交、推送、发布。源码引入前记录依赖和许可证，所有开发与验收进度以 docs/IMPLEMENTATION.md 为准。
